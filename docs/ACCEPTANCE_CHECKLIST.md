## I. Requirement 8 鈥?JSON import/export

### Export
- [ ] Exported JSON includes schema metadata/version.
- [ ] Export includes models.
- [ ] Export includes cases/evidence.
- [ ] Export includes model responses.
- [ ] Export includes human reviews.
- [ ] Exported data can be imported back successfully.

### Import
- [ ] Malformed JSON is rejected with a readable error.
- [ ] Structurally invalid JSON is rejected with a readable error.
- [ ] Duplicate IDs are rejected.
- [ ] Response references to unknown case/model are rejected.
- [ ] Review references to unknown case/model are rejected.
- [ ] Invalid scores/status/tags are rejected.
- [ ] Invalid import leaves current workspace unchanged.
- [ ] Valid import uses replace semantics after confirmation.
- [ ] Valid imported workspace survives refresh.

## J. Program-generated report

- [ ] Report is generated by application code, not manually calculated.
- [ ] Report states schema version and generation timestamp.
- [ ] Report states completed-review coverage.
- [ ] Report includes four-model ranking.
- [ ] Report includes five dimension averages.
- [ ] Report includes failure-tag distribution.
- [ ] Report includes case-level comparison information.
- [ ] Report explicitly states that only completed reviews count toward ranking.
- [ ] One generated report is checked into the repository before submission.

## K. Automated tests

Minimum submission requirement is 3; target is these 6 critical behaviors:

- [ ] `saveReview`: new review persists correctly.
- [ ] `updateReview`: same case/model updates without duplicate review.
- [ ] `restoreWorkspace`: persisted workspace reloads after store recreation/refresh equivalent.
- [ ] `calculateRanking`: known fixture produces exact expected totals/rank order.
- [ ] `failureTagDistribution`: known fixture produces exact tag counts.
- [ ] `importValidation`: invalid bundle is rejected and valid bundle is accepted.

Test quality rule:
- [ ] Critical tests assert exact expected values/behavior, not merely `toBeDefined()` or snapshots with no semantic assertion.

## N. Explicit anti-overengineering checks

The following should remain **absent** unless the frozen specification is changed for a mandatory reason:

- [ ] No backend server.
- [ ] No relational or vector database.
- [ ] No authentication/RBAC.
- [ ] No real external model/API integration.
- [ ] No LLM auto-judge.
- [ ] No WebSocket/streaming.
- [ ] No Docker/Kubernetes requirement.
- [ ] No generic repository/factory/DI framework.
- [ ] No duplicated analytics formulas in Vue components.
- [ ] No feature added solely because Codex suggested it.

## Gate 0 exit condition

Gate 0 is complete when:
1. `PROJECT_SPEC.md`, `DATA_CONTRACT.md`, and this checklist are mutually consistent;
2. no unresolved decision can materially change data structures, scoring, persistence, import semantics, or analytics semantics;
3. no business implementation has been started yet;
4. the frozen documents are committed before Gate 1 begins.
